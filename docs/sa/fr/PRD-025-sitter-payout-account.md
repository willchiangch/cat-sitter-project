## 1. 背景與目的

線下轉帳需要飼主知道匯到哪個帳戶。保母在「我的」設定自己的收款帳號；每筆 CHARGE payment 建立時快照這組帳號（baseline §3.3、CQ-23），飼主付款頁只顯示快照（PRD-007）。本卡只處理帳號本身的設定、權限、保護；自 PRD-007 拆出，因為帳號資料歸 SD-SUPPLY、快照與付款歸 SD-ORDER（doc-conventions：子流程分屬不同模組時拆 PRD）。

## 2. 使用者故事

- **US-1** 身為保母，我希望設定與修改我的收款帳號，以便飼主匯款到正確帳戶。
- **US-2** 身為保母，我希望修改帳號時只影響之後的新款項，且帳號被改動時我會收到通知，以便發現被盜改。

## 3. 角色與權限

| 動作 | OWNER | SITTER | ADMIN | 匿名 | 方案限制 |
|------|-------|--------|-------|------|---------|
| 檢視自己的收款帳號 | ✗ 403 `ROLE_MISMATCH` | 本人 | ✗（即時帳號不開放；快照見 PRD-007 CQ-12） | ✗ 401 | 無 |
| 設定 / 修改自己的收款帳號 | ✗ 403 `ROLE_MISMATCH` | 本人 | ✗ 403 `ROLE_MISMATCH` | ✗ 401 | 無；訂閱鎖定 / 停權不擋（BR-5） |
| 讀取他人的收款帳號 | ✗ | ✗ | ✗ | ✗ | — |

- 端點以 token 身分定位「自己的」帳號，不接受 sitter ID 參數；因此不存在讀他人帳號的路徑（§1.2）。

## 4. 主流程

### 4.1 設定 / 修改

1. 保母進入「我的 > 收款帳號」。未設定時顯示「尚未設定收款帳號」與設定表單。
2. 填寫銀行代碼、分行、帳號、戶名，送出。
3. 系統驗證欄位 → 加密存放 → 寫稽核紀錄（操作者、時間、變更前後之帳號後五碼）→ `enqueue` 通知保母本人「收款帳號已變更」（站內 + Email，內容不含完整帳號）。
4. 之後建立的 CHARGE payment 快照新帳號；既有 `UNPAID` / `SUBMITTED` payment 的快照不變（CQ-23，顯示見 PRD-007 AC-1.1）。

## 5. 狀態轉移

無（帳號沒有狀態機）。

## 6. 業務規則

| # | 規則 | 出處 |
|---|------|------|
| BR-1 | 欄位：銀行代碼、分行、帳號、戶名，驗證規則見 CQ-1 | 沿用原 PRD-007（A.2 欄位）；格式見 CQ-1 |
| BR-2 | 只有該保母本人可讀寫自己的即時收款帳號 | baseline §1.2 |

## 8. 驗收標準（AC）

### 子模組 1：收款帳號設定

- [ ] **AC-1.1 (首次設定)**：Given 保母尚未設定收款帳號，When 開啟「我的 > 收款帳號」，Then 顯示「尚未設定收款帳號」；When 填入銀行代碼「812」、分行「台北分行」、帳號「12345678901」、戶名「王小明」並送出，Then 200，重新讀取回傳相同四個值。對應：BR-1、BR-2
- [ ] **AC-1.2 (欄位驗證)**：When 銀行代碼「81」、帳號含非數字、戶名空白任一，Then 400 `VALIDATION_FAILED`，已存帳號不變。對應：BR-1、EX-4
- [ ] **AC-1.3 (權限)**：When 以 OWNER 角色 token 讀或寫收款帳號，Then 403 `ROLE_MISMATCH`；When ADMIN 呼叫，Then 403 `ROLE_MISMATCH`；When 未登入，Then 401 `UNAUTHENTICATED`。對應：BR-2、EX-1、EX-2
- [ ] **AC-1.4 (修改只影響新款項)**：Given 訂單 A 的 INITIAL payment `UNPAID` 快照帳號 X，When 保母把帳號改為 Y，Then A 的付款頁仍顯示 X（PRD-007 AC-1.1）；When 之後保母對訂單 B 報價，Then B 的 INITIAL payment 快照為 Y。對應：BR-3
- [ ] **AC-1.5 (加密與稽核)**：When 保母把帳號由 X 改為 Y，Then 資料庫中帳號欄位的儲存值不等於明文「12345678901」；新增 1 筆稽核紀錄（操作者 = 該保母、時間、變更前後後五碼）；以相同值重送不新增稽核紀錄。對應：BR-4、EX-7
- [ ] **AC-1.6 (變更通知)**：When 保母修改帳號成功，Then 保母收到「收款帳號已變更」站內通知 1 則並排入 Email 1 封，內容只含帳號後五碼；Resend 失敗時修改仍為 200 且站內通知存在。對應：BR-4、EX-9、CQ-4
- [ ] **AC-1.7 (訂閱鎖定不擋)**：Given 保母訂閱已逾期鎖定，When 修改收款帳號，Then 200。對應：BR-5、EX-6
- [ ] **AC-1.8 (不可刪除)**：Given 已設定帳號，Then 頁面無刪除按鈕；When 呼叫刪除，Then 該端點不存在（405）。對應：BR-6、CQ-3

## 9. 影響範圍

| 面向 | 內容 |

| 資料 | 保母收款帳號（銀行代碼、分行、帳號（加密）、戶名、更新時間）；收款帳號稽核紀錄。歸 SD-SUPPLY；SD-ORDER 透過 SD-SUPPLY 的 Service 於建立 CHARGE payment 時讀取並快照 |
