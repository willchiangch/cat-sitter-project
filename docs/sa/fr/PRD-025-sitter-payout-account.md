## 1. 背景與目的

線下轉帳需要飼主知道匯到哪個帳戶。保母在「我的」設定自己的收款帳號；每筆 CHARGE payment 建立時快照這組帳號（baseline §3.3、CQ-23），飼主付款頁只顯示快照（PRD-007）。本卡只處理帳號本身的設定、權限、保護；自 PRD-007 拆出，因為帳號資料歸 SD-SUPPLY、快照與付款歸 SD-ORDER（doc-conventions：子流程分屬不同模組時拆 PRD）。

## 2. 使用者故事

- **US-1** 身為保母，我希望設定與修改我的收款帳號，以便飼主匯款到正確帳戶。
- **US-2** 身為保母，我希望修改帳號時只影響之後的新款項，且帳號被改動時我會收到通知，以便發現被盜改。

## 3. 角色與權限

| 動作 | OWNER | SITTER | ADMIN | 匿名 | 方案限制 |
|------|-------|--------|-------|------|---------|
| 檢視自己的收款帳號 | ✗ 403 `ROLE_MISMATCH` | 本人 | ✗ 403 `ROLE_MISMATCH`（即時帳號不開放；可讀訂單範圍內唯讀 payment 快照，baseline §1.2、CQ-66，畫面在 PRD-007） | ✗ 401 | 無 |
| 設定 / 修改自己的收款帳號 | ✗ 403 `ROLE_MISMATCH` | 本人 | ✗ 403 `ROLE_MISMATCH` | ✗ 401 | 無；訂閱鎖定 / 停權不擋（BR-5） |
| 讀取他人的收款帳號 | ✗ | ✗ | ✗ | ✗ | — |

- 端點以 token 身分定位「自己的」帳號，不接受 sitter ID 參數；因此不存在讀他人帳號的路徑（§1.2）。

## 4. 主流程

### 4.1 設定 / 修改

1. 保母進入「我的 > 收款帳號」。未設定時顯示「尚未設定收款帳號」與設定表單。
2. 填寫銀行代碼（3 位數字）、分行（1–30 字）、帳號（10–16 位數字）、戶名（1–50 字），四欄皆必填，送出（BR-1）。
3. 系統驗證欄位 → 加密存放 → 寫稽核紀錄（操作者、時間、變更前後之帳號後五碼）→ `enqueue` 通知保母本人「收款帳號已變更」（站內 + Email，只顯示帳號後五碼，BR-8）。
4. 之後建立的 CHARGE payment 快照新帳號；既有 `UNPAID` / `SUBMITTED` payment 的快照不變（CQ-23，顯示見 PRD-007 AC-1.1）。
5. 帳號只能修改、不能刪除（BR-6）；一經設定，保母即永遠滿足 O2「已設定收款帳號」前置條件。

### 4.2 未設定時報價（引用）

保母尚未設定收款帳號就報價 → O2 前置條件不符，422 `PAYOUT_ACCOUNT_REQUIRED`（baseline §3.2 O2、§3.7、CQ-63）。檢查與驗收由 PRD-006 承擔；本卡只提供「是否已設定」的查詢給 SD-ORDER（BR-9）。

## 5. 狀態轉移

無（帳號沒有狀態機）。

## 6. 業務規則

| # | 規則 | 出處 |
|---|------|------|
| BR-1 | 欄位皆必填：銀行代碼 = 3 位數字（`^[0-9]{3}$`）；分行 = 去除前後空白後 1–30 字；帳號 = 10–16 位數字（`^[0-9]{10,16}$`）；戶名 = 去除前後空白後 1–50 字 | 沿用原 PRD-007（A.2 欄位）；格式 CQ-1 |
| BR-2 | 只有該保母本人可讀寫自己的即時收款帳號 | baseline §1.2 |
| BR-3 | 修改只影響之後建立的 CHARGE payment；既有 payment 的快照不變 | baseline §1.2、§3.3、CQ-23 |
| BR-4 | 帳號加密存放；每次修改寫稽核紀錄 | CQ-23（使用者採第 1 輪建議預設值「加密存放、並寫紀錄」） |
| BR-5 | 訂閱逾期 / 停權時仍可修改收款帳號（§2.2 鎖定範圍只列方案 / 問卷 / 公開檔案設定；BR §5.7.2 鎖定時保留「我的」頁） | baseline §2.2、BR §5.7.2 |
| BR-6 | 收款帳號只能修改，不能刪除（避免已報價待補款時無帳號可快照）；不提供刪除端點 | CQ-3 |
| BR-7 | 同一保母多裝置同時修改不做併發保護，最後寫入者為準 | doc-conventions（不處理同一使用者多裝置自我併發） |
| BR-8 | 每次修改成功（值有變動）通知保母本人「收款帳號已變更」，站內 + Email 各一則；通知內容與稽核紀錄只呈現帳號後五碼，不含完整帳號 | 抽樣 #11（防盜改）；CQ-4 |
| BR-9 | 未設定收款帳號的保母不能報價：O2 前置條件「已設定收款帳號」，不符回 422 `PAYOUT_ACCOUNT_REQUIRED`；檢查在 PRD-006 的 O2，本卡不重複定義 | baseline §3.2 O2、§3.7、CQ-63；CQ-2 |

## 8. 驗收標準（AC）

### 子模組 1：收款帳號設定

- [ ] **AC-1.1 (首次設定)**：Given 保母尚未設定收款帳號，When 開啟「我的 > 收款帳號」，Then 顯示「尚未設定收款帳號」；When 填入銀行代碼「812」、分行「台北分行」、帳號「12345678901」、戶名「王小明」並送出，Then 200，重新讀取回傳相同四個值；Given 該保母仍未設定帳號時對 PENDING 訂單報價，Then 422 `PAYOUT_ACCOUNT_REQUIRED`、訂單仍 `PENDING`（PRD-006 驗收，本卡僅確認碼名一致），設定完成後同一報價可成功。對應：BR-1、BR-2、BR-9、EX-10
- [ ] **AC-1.2 (欄位驗證)**：When 銀行代碼「81」或「8123」、分行空白或 31 字、帳號 9 位或 17 位或含非數字、戶名空白或 51 字任一，Then 400 `VALIDATION_FAILED`，已存帳號不變；When 銀行代碼「812」、分行 30 字、帳號 10 位與 16 位、戶名 50 字，Then 200。對應：BR-1、EX-4
- [ ] **AC-1.3 (權限)**：When 以 OWNER 角色 token 讀或寫收款帳號，Then 403 `ROLE_MISMATCH`；When ADMIN 呼叫，Then 403 `ROLE_MISMATCH`；When 未登入，Then 401 `UNAUTHENTICATED`。對應：BR-2、EX-1、EX-2
- [ ] **AC-1.4 (修改只影響新款項)**：Given 訂單 A 的 INITIAL payment `UNPAID` 快照帳號 X，When 保母把帳號改為 Y，Then A 的付款頁仍顯示 X（PRD-007 AC-1.1）；When 之後保母對訂單 B 報價，Then B 的 INITIAL payment 快照為 Y。對應：BR-3
- [ ] **AC-1.5 (加密與稽核)**：When 保母把帳號由 X 改為 Y，Then 資料庫中帳號欄位的儲存值不等於明文「12345678901」；新增 1 筆稽核紀錄（操作者 = 該保母、時間、變更前後後五碼）；以相同值重送不新增稽核紀錄。對應：BR-4、EX-7
- [ ] **AC-1.6 (變更通知)**：When 保母修改帳號成功，Then 保母收到「收款帳號已變更」站內通知 1 則並排入 Email 1 封，內容只含帳號後五碼（例「…78901」），不出現完整帳號；以相同值重送不發通知；Resend 失敗時修改仍為 200 且站內通知存在。對應：BR-4、BR-8、EX-9
- [ ] **AC-1.7 (訂閱鎖定不擋)**：Given 保母訂閱已逾期鎖定，When 修改收款帳號，Then 200。對應：BR-5、EX-6
- [ ] **AC-1.8 (不可刪除)**：Given 已設定帳號，Then 頁面無刪除按鈕；When 呼叫刪除，Then 該端點不存在（405），帳號仍在。對應：BR-6、EX-11
