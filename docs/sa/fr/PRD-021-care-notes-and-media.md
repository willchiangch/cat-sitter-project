## 背景與目的

在訂單之外，保母與飼主之間需要一個「長期共用的照護資訊空間」，用於記錄服務執行的注意事項、聯絡資訊、喜好與相關媒體（如環境照片、設備說明），以確保每次服務的品質一致，並作為雙方溝通與留存記錄的依據。此功能與訂單完全解耦，屬於「保母-飼主關係層」的資料。

## 使用者故事

- 身為 **保母**，我希望能為特定飼主建立並維護一份照護記事本，方便在服務前快速回顧所有注意事項。
- 身為 **保母**，我希望能將常用的記事內容儲存為最多 3 個模板，以便對新飼主快速套用。
- 身為 **保母**，我希望能上傳最多 20 張照片或影片，用於提醒飼主環境資訊（如：水盆位置、餵食器更換方式）。
- 身為 **飼主**，我希望在保母更新記事本或媒體庫時，能收到通知，以便知悉最新的服務說明。

---

## 功能規格

### A. 照護記事本 (Care Notes)

**記事本結構**：
- 一份記事本由多個「大項 (Section)」組成，固定分類如下（不可新增或刪除大項分類）：
  1. 主要服務內容
  2. 聯絡資訊
  3. 注意事項
  4. 喜好
  5. 醫院
  6. 其他
- 每個大項內，保母可以**新增條目 (Item)**，每個條目包含：
  - `標題`：單行文字。
  - `詳細內容`：多行文字（支援換行輸入）。
  - `顯示序號`：系統根據排列順序自動生成 (1, 2, 3...)。
- **排序與編輯**：
  - 支持**拖拽排序**：保母可以手動調整條目在大項內的上下順序。
  - 條目刪除後，系統自動重新計算剩餘條目的顯示序號，保持連續性。

**模板系統**：
- 保母對**任意飼主**的記事本，可點擊「儲存為範本」。
- 每位保母最多持有 **3 個模板**（跨所有飼主共用上限）。
- 模板超過上限時，系統提示保母選擇覆蓋其中一個現有模板，不得新增。
- 套用模板時，模板內容複製進當前記事本（不覆蓋已有內容，採追加模式）。

**通知**：
- 保母每次儲存記事本更新後，系統自動傳送站內訊息通知給對應飼主：「保母已更新您的照護記事本，請前往查閱。」
- 飼主僅能查看記事本，**不可自行編輯**；若需修改，飼主需透過其他管道聯繫保母。

---

### B. 照護媒體庫 (Care Media Library)

- 保母對同一飼主，可上傳合計最多 **20 組媒體（照片或影片）**。
- 每組媒體包含：
  - `說明文字`：描述這張照片/影片的用途（如：「水盆位置在廚房右側」）。
  - 媒體檔案本體（照片或影片）。
- 超過 20 組時，必須先刪除現有媒體才能上傳新的。
- 媒體庫更新（上傳或刪除）後，系統自動傳送站內訊息通知飼主：「保母已更新您的環境說明媒體庫。」

**媒體存取與儲存（2026-11-22 依 NFR-003 回寫）**：
- 照護媒體一律存為**私有物件**，放在私有 bucket（只有保母頭像放公開 bucket，見 PRD-013「媒體儲存分類」）；上傳時不得設定 `allUsers` 讀取權限（NFR-003 SEC-FILE-1、CQ-17）。
- 可讀者：該配對關係的保母與飼主（「建立關係的前提」成立者）；ADMIN 是否可讀見 CQ-1。非配對當事人 → 403 `FORBIDDEN`，媒體不存在 → 404 `NOT_FOUND`（baseline §1.2 共通規則）；拒絕時不簽發網址。
- 讀取只用每次授權檢查後產生的 GCS 簽名網址，`X-Goog-Expires=900`（15 分鐘，NFR-003 CQ-18）；API 回應不含未簽名網址；簽名網址不寫入 DB、不寫入冪等回放 body（SEC-FILE-2.5）。
- 上傳格式以檔案內容（magic bytes）判斷，物件 `Content-Type` 與物件鍵副檔名由伺服器依判定格式設定，不沿用客戶端宣告與檔名；SVG、HTML、PDF 一律拒絕；格式白名單與大小上限由 SD-CARE 定（NFR-003 SEC-FILE-3、FILE-4）。
- 簽名網址過期後前端需重新呼叫讀取 API 取得新網址。

## 例外處理

| 情境 | 預期行為 |
|------|---------|
| 模板數量已達 3 個，嘗試儲存新範本 | 系統彈出選擇框，要求保母選擇覆蓋哪一個現有模板，確認後才儲存。 |
| 媒體數量已達 20 組，嘗試上傳 | 前端阻擋上傳，提示「已達上限，請先刪除現有媒體」。 |
| 飼主嘗試編輯記事本 | 介面僅顯示唯讀模式，不提供任何編輯入口。 |
| 保母與飼主之間沒有任何訂單，卻嘗試讀寫兩人的記事本或媒體庫 | 系統拒絕（403），不建立任何資料。 |
| 非配對當事人（第三位使用者）以媒體 ID 呼叫讀取 API（BOLA） | 403 `FORBIDDEN`，不簽發簽名網址。 |
| 以未簽名網址 `https://storage.googleapis.com/{bucket}/{objectKey}` 匿名讀取照護媒體 | GCS 回 401 或 403，body 不含物件內容。 |
| 簽名網址超過 900 秒後開啟 | GCS 拒絕；前端重新呼叫讀取 API 取得新網址。 |
| 上傳內容為 HTML / SVG 但宣告為圖片 | 422（模組碼由 SD-CARE 定），不留下 GCS 物件。 |
| GCS 簽發或上傳失敗 | 503 `STORAGE_UNAVAILABLE`（baseline §3.7），不建立媒體紀錄。 |

## 資料規則 / 業務規則

- **資料歸屬**：記事本與媒體庫屬於「保母-飼主配對關係」的資料，不受單一訂單狀態影響。
- **建立關係的前提（2026-10 產品決策）**：保母與飼主之間 **有過任何狀態的訂單**（含待評估、已取消、已結案）才算配對關係，才能讀取或寫入兩人的記事本與媒體庫；沒有訂單的保母不能對任意飼主建立記事本或上傳媒體。
- **顯示序號**：序號僅作為視覺呈現使用，刪除或移動條目時會即時重新編號。

## 驗收標準（AC）

- [ ] **AC-1 (大項不可變)**：記事本固定顯示 6 個大項分類，不可新增 or 刪除分類。
- [ ] **AC-2 (條目序號與排序)**：在任一大項內新增條目，系統自動顯示序號；刪除或拖拽條目後，序號必須保持 1, 2, 3... 連續性。
- [ ] **AC-3 (模板儲存)**：成功儲存範本後，模板數量上限為 3，超過時必須觸發覆蓋選擇流程。
- [ ] **AC-4 (記事本通知)**：保母更新記事本後，對應飼主必須在站內收到通知。
- [ ] **AC-5 (飼主唯讀)**：飼主登入後只能查看記事本，介面上不存在任何編輯按鈕。
- [ ] **AC-6 (媒體上限)**：保母對同一飼主上傳第 21 組媒體時，系統必須阻擋並顯示錯誤提示。
- [ ] **AC-7 (媒體通知)**：媒體庫更新後，對應飼主必須在站內收到通知。
- [ ] **AC-8 (配對關係前提與媒體私有存取)**：情境 1：保母與飼主之間沒有任何訂單時，雙方讀取、保母寫入該配對的記事本與媒體庫都必須被拒絕（403）。情境 2：Given 保母 S 與飼主 O 有訂單、S 上傳媒體 m1，When O 呼叫讀取，Then 200，回應中 m1 的網址帶 `X-Goog-Signature` 且 `X-Goog-Expires=900`；When 第三位飼主 P 以 m1 的 ID 呼叫讀取，Then 403 `FORBIDDEN`、回應不含任何網址。情境 3：When 以未簽名網址 `https://storage.googleapis.com/{bucket}/{m1 objectKey}` 匿名 GET，Then 401 或 403，body 不含物件內容；m1 所在 bucket 不是保母頭像的公開 bucket。
