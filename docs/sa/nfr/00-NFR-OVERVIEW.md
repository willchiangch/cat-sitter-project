# 非功能性需求 (Non-Functional Requirements) 大綱

> **建立日期**：2026-05-09
> **狀態**：Draft
> **適用範圍**：貓咪保母 PWA 全系統

---

## NFR-001: 效能需求 (Performance)

### 回應時間
- 一般頁面載入：首次載入 ≤ 3 秒、後續換頁 ≤ 1.5 秒。
- 訂單送出 / 報價確認等寫入操作：回應時間 ≤ 2 秒。

### 多媒體處理
- 照片上傳：前端自動壓縮至 1MB 以下再傳送，單張上傳完成 ≤ 5 秒 (4G 網路環境)。
- 影片上傳：支援背景非同步上傳，不阻塞使用者操作。

### 行事曆同步
- 訂單狀態變更後，行事曆事件更新延遲應 ≤ 5 分鐘。

---

## NFR-002: 可用性與可靠性 (Availability & Reliability)

### 系統可用性
- 目標 SLA：99.5% (每月停機時間 ≤ 3.6 小時)。
- 排程維護作業 (如凌晨清理排程) 不得影響前端使用者操作。

### 錯誤容忍
- 第三方服務 (Google Calendar、金流 API) 無法連線時，系統核心功能 (接單/報價/服務紀錄) 不得中斷。
- 金流回呼 (Webhook) 失敗時，需具備重試機制，確保交易最終一致性。

## NFR-003: 安全性 (Security)

> 完整規格：`docs/sa/nfr/03-SECURITY.md`（Approved，使用者核准 2026-11-22，CQ-1 ~ CQ-52 採建議值）。本段只是摘要，與該文件不一致時以該文件為準。所有限制不依 SaaS 方案等級區分。

### 身份認證（SEC-AUTH）
- 密碼只存加鹽單向雜湊（BCrypt cost ≥ 10 或 Argon2id）；密碼 8–64 字元且 UTF-8 ≤ 72 bytes。
- access token 15 分鐘、演算法固定 HS256、payload 不含方案與個資；refresh token 7 天、每次換發輪替、同一 family 30 天絕對上限，改存 httpOnly cookie；refresh token、重設憑證、OTP 只存雜湊。
- 連續登入失敗 5 次以 Email 維度鎖定 10 分鐘（不存在的 Email 也鎖，429 `ACCOUNT_LOCKED`），跑假雜湊避免帳號列舉。
- Google 登入驗證 `iss`、`aud`、`email_verified`；WebAuthn challenge 單次使用、限白名單 origin。
- ADMIN 為獨立無密碼帳號，只能以 WebAuthn 登入，不能經切換角色取得。
- 改密碼須帶目前密碼、綁定 WebAuthn 前須再驗證；改密碼、重設密碼、登出所有裝置、停用帳號後撤銷 session。

### 授權（SEC-AZ）
- 身分一律取自 token；越權統一回 403 `FORBIDDEN` / `ROLE_MISMATCH`、401、404（判斷順序依 baseline §3.7）；每支端點明確宣告存取規則，匿名白名單逐條列出。
- 方案權限即時查詢，不放進 token。

### 資料保護（SEC-DATA、SEC-SECRET、SEC-FILE）
- 收款帳號與快照以 AES-256-GCM 加密；金鑰與所有 secret 只經 Secret Manager 注入、無預設值。
- 公開與私有物件分 bucket：只有保母頭像公開；KYC（本人與 ADMIN 可讀）、付款 / 退款憑證、照護日誌媒體、照護媒體、毛孩頭像皆私有，以短效簽名網址讀取（憑證與 KYC 300 秒，日誌媒體、照護媒體、毛孩頭像 900 秒）。
- 上傳以 magic bytes 判斷格式、伺服器端強制大小上限。
- **修改收款帳號不要求再驗證**（使用者 2026-11-22 決定；取代本段舊稿「銀行帳戶變更需二次驗證」），改以不可關閉的變更通知偵測盜改。

### 傳輸與網頁（SEC-WEB）
- 全站 HTTPS；前端與 API 各自下發資安標頭（CSP、HSTS 等）；CORS 白名單；前端導頁只允許站內相對路徑；使用者內容輸出端轉義。

### 濫用防護（SEC-INPUT）
- 全域限流：匿名每 IP 每分鐘 60 次、登入者每身分每分鐘 300 次，超過 429 `RATE_LIMITED` + `Retry-After`；寄信類匿名端點每 Email 每小時 5 封、每 IP 20 封。
- 請求 body、分頁筆數、數值範圍、regex 輸入長度皆有上限；後端不對使用者提供的 URL 發請求。

### 日誌、稽核與供應鏈（SEC-LOG、SEC-AUDIT、SEC-INT、SEC-SCA）
- log 遮蔽 token、密碼、secret、完整帳號；錯誤回應不洩漏內部細節。
- 稽核與主操作同交易、append-only、交易相關稽核保存 ≥ 5 年。
- `/api/internal/**` 只認 `X-Internal-Secret`；測試端點不得觸及真實使用者資料。
- CI 依賴漏洞掃描、Critical 7 天 / High 30 天修補、框架在官方支援期內、Actions 釘 SHA。

## NFR-004: 可擴展性 (Scalability)

### 使用者規模
- MVP 階段目標承載：500 位活躍保母、5,000 位活躍飼主。
- 系統架構設計需能水平擴展，預留年增長 3 倍之空間。

### 儲存規模
- 多媒體檔案預估量：每月新增 50GB (依活躍保母數與方案分布)。
- 系統需具備根據 PRD-013 保留策略自動回收儲存空間之能力。

---

## NFR-005: 相容性 (Compatibility)

### 瀏覽器支援
- **主要支援**：Chrome (最近兩個主要版本)、Safari (iOS 15+)。
- **次要支援**：Firefox、Edge。
- **不支援**：Internet Explorer。

### 裝置支援
- PWA 必須在 iOS (Safari) 與 Android (Chrome) 裝置上均可「加入主畫面」並正常運作。
- 介面需採用響應式設計 (Responsive Design)，最小支援寬度 375px (iPhone SE)。

### 生物辨識
- WebAuthn 功能需偵測裝置是否支援，不支援時自動隱藏，不得造成錯誤。

## NFR-006: 可維護性 (Maintainability)

### 程式碼品質
- 前後端皆需遵循團隊制定的 Code Style 規範 (Lint / Formatter)。
- 單元測試覆蓋率目標：核心業務邏輯 (金額計算、狀態機轉換) ≥ 80%。

### 日誌與可觀測性
- 所有 API 請求需記錄請求時間、回應狀態碼、處理耗時。
- 關鍵業務操作 (訂單建立/結案/付款/退款) 需寫入業務日誌，含操作者、時間戳與變更前後值。
- 生產環境錯誤需即時通知開發團隊 (如透過 Slack 或 Email Alert)。

### 部署
- 支援 CI/CD 自動化部署流程。
- 資料庫 Schema 變更需透過版本化的 Migration 工具管理。

---

## NFR-007: 離線能力 (Offline Support - PWA)

### 基礎離線支援
- PWA 需註冊 Service Worker，確保在網路短暫中斷時，已載入的頁面仍可瀏覽。
- 保母在服務現場網路收訊不良時，照片上傳應支援排隊機制，待網路恢復後自動重傳。

### 限制
- 離線狀態下不支援訂單建立、付款或狀態變更等需要後端參與的操作。

---

## NFR-008: 法規遵循 (Compliance)

### 個資保護
- 系統需符合台灣《個人資料保護法》之要求。
- 使用者註冊時需明確告知資料蒐集目的與範圍 (已在 PRD-000 設計條款同意機制)。
- 使用者有權要求刪除帳號與相關資料 (待 FR 補充帳號註銷流程)。

### 服務條款
- 平台服務條款與隱私權政策需於使用者首次使用前取得同意。
- 付費方案需另有獨立的付費服務條款 (已在 PRD-012 設計)。

### 金流合規
- 代收代付行為需符合主管機關之相關規範。
- 所有交易紀錄需保存至少 5 年以供查核。

---

## NFR-009: 國際化與在地化 (i18n / L10n)

### 語系
- MVP 階段僅支援繁體中文 (zh-TW)。
- 系統架構應預留多語系擴充能力 (如前端文字抽離為 i18n Key)。

### 時區與貨幣
- 時區：系統固定使用 `Asia/Taipei`。
- 貨幣：統一使用新台幣 (TWD)，金額計算使用 `BigDecimal(18,4)`。
